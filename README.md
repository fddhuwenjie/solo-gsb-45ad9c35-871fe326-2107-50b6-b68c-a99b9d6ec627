# 本地双卷印发校核（Dual Paper Check）

一个完全本地运行的单选题双卷（A/B 卷）印发与答案校核网页：

- **题库**：录入题干、四个选项并指定正确选项；每道题（`Q#`）和每个选项（`O#`）都有稳定标识。
- **编排**：分别调整 A、B 卷的题序和每题四个选项的顺序，草稿可保存。
- **封存**：A、B 两卷从同一题库修订封存为一个版本，封存时复制题干、选项、答案的**快照**。
- **打印**：每个封存版本可分别打印 A/B 卷的**试卷、答题卡、答案表**；答题卡上的题号与选项字母与对应卷面完全一致。
- **封存即冻结**：封存后再编辑题库，不改变任何已封存卷面和答题卡。
- **勘误**：若发现答案错误，按封存题目和封存时印出的选项提交勘误：
  - 同时更新 A、B 两卷答案表，记录各卷题号及勘误前后的选项字母；
  - 选项不属于该封存题目、或任一卷缺少该题映射时，**整次拒绝，原答案不变**（事务保证）；
  - 保留每次勘误记录，可随时回看。
- **作答登记**：在封存详情页选 A 或 B 卷，输入考生编号并按该卷印出的题号逐题登记作答字母（可留空）：
  - 每题 1 分，空白计 0 分；登记时保存作答对应的**封存选项**、逐题得分与总分；
  - 同一考生在同一封存版本只能登记一张；
  - 题号缺失、重复、多余，或字母不属于该题时，**整张拒绝且不留下任何记录**。
- **成绩复核**：回看答题卡时同时显示**登记成绩**与**当前成绩**（按最新答案表对原作答的封存选项重新核分）：
  - 列出勘误后得分变化的题号及前后分数；
  - 多次勘误可使成绩上升、下降或恢复，登记成绩与作答记录始终不变；
  - 修改题库、其他封存版本或失败的勘误都不会影响复核结果。
- **成绩发布批次**：在封存详情页一次性发布该版本**当前已登记的全部答题卡**：
  - 按卷别、考生编号排序列出总分，并保存每张卡按印出题号排列的**逐题得分**；
  - 没有答题卡时**拒绝发布**；
  - 名单与得分取自**同一个数据库状态**：登记或勘误与发布交错时，各项变化要么整体归入本批、要么整体留到下批，绝不会出现“旧名单配新答案”（发布以 `BEGIN IMMEDIATE` 单事务完成，与登记 / 勘误互斥）；
  - 已发布批次立即**冻结**，之后的登记、勘误或题库修改都不改变它；
  - 再次发布时与上一批**逐人对照**：标出新登记者、总分变化，以及逐题变化的题号与前后分数；即使总分相抵，逐题变化也照常显示；
  - 每批名单与成绩明细都可在页面回看。

技术栈：Python Flask + SQLite（后端）、原生 JavaScript（前端，无构建步骤）、Gunicorn + Docker。

## 一条命令启动

需要本机已安装 Docker 与 Docker Compose 插件：

```bash
docker compose up -d --build
```

启动后在浏览器打开：

**http://localhost:8000**

端口为容器内 **8000**，已映射到宿主机同端口。停止：`docker compose down`（数据保留在 Docker 卷 `exam-data` 中）。

如需更换宿主机端口，修改 `docker-compose.yml` 中的 `"8000:8000"` 左侧端口即可。

## 页面与使用流程

1. `题库`（`/#/questions`）：新增 / 编辑 / 删除单选题。已被封存引用的题目会显示提示——编辑只影响今后封存。
2. `A/B 卷编排`（`/#/arrange`）：上下调整两卷题序；每题选项可下拉换位、一键顺移或恢复题库顺序；填备注后点“保存并封存新版本”。
3. `封存卷与勘误`（`/#/seals`）：列出所有封存版本；点入后用标签页切换 A/B 卷的试卷、答题卡、答案表，点“打印 / 另存 PDF 当前页”输出。
4. 在封存详情页的“勘误”标签中按封存题目 + 封存选项提交修正，可一次提交多条；成功后两卷答案表立即更新（带 `*` 标注勘误题），下方列出历次勘误（各卷题号、勘误前后字母、选项稳定标识）。
5. 在封存详情页的“作答登记 / 复核”标签中：
   - **登记**：选择 A / B 卷，填考生编号，按该卷印出的题号逐题选择作答字母（不选即空白），点“登记答题卡”。校验不通过（题号缺失 / 重复 / 多余、字母不属于该题、考生重复登记）时整张拒绝、不留记录；
   - **复核**：下方列表展示每张答题卡的登记成绩与当前成绩，点“查看复核”看逐题对照；勘误生效后当前成绩随之升降或恢复，变化题号及前后分数在详情中高亮列出。
6. 在封存详情页的“成绩发布 / 回看”标签中发布与回看成绩批次：
   - **发布**：点“发布当前全部答题卡成绩”，系统把当前已登记的全部答题卡（按卷别、考生编号排序）及其逐题得分冻结为一个批次；没有答题卡时按钮禁用并拒绝发布。与发布同时进行的登记 / 勘误会被事务挡住，要么整体进本批，要么整体等下批；
   - **回看**：下方“已发布批次”按批次倒序列出发布时间、人数及与上批的对照摘要（新登记者、总分变化、逐题变化数）；点“回看明细”查看本批完整名单与成绩矩阵（每人一行、按印出题号逐题显示作答字母与得分，黄底标出与上批得分不同的题目，悬停可见前后分数）；
   - **再次发布**：先在“作答登记 / 复核”或“勘误”标签完成新登记 / 勘误，再回本标签发布；新批次自动与上一批逐人对照——新登记者带“新登记”标记，总分变化列出前后总分，**总分相抵时逐题变化仍在矩阵中黄底标出并在对照卡片中单列**；
   - 任何已发布批次都不随之后的登记、勘误或题库修改改变，随时可点入回看。

## 本地直接运行（不用 Docker）

```bash
pip install -r requirements.txt
python -m flask --app server.app run --host 0.0.0.0 --port 8000
# 或：gunicorn -b 0.0.0.0:8000 server:app
```

数据库默认存于 `./data/exam.db`，可用环境变量 `DATABASE_PATH` 修改；首次启动自动建表。

## 数据模型要点

- `question / option / bank_answer`：现行题库与答案。
- `paper_draft*`：A/B 卷编排草稿。
- `seal / sealed_question / sealed_option`：封存版本及题干、选项、答案快照。
- `paper / paper_question / paper_option`：封存卷中每题的题号（number）与选项字母（A–D），是卷面与答题卡一致性的依据。
- `erratum_batch / erratum_item`：勘误批次与明细（A/B 卷勘误前后字母）；勘误提交为单事务，校验不过整体回滚。
- `answer_sheet / answer_sheet_item`：登记的答题卡与逐题作答。作答保存的是**封存选项**快照 id 与登记得分；`(seal_id, examinee)` 唯一，保证同一考生在同一版本只有一张。复核时的当前成绩由封存选项对应当前答案实时算出，不落库，因此勘误、题库改动、其他版本都不会污染登记数据。
- `score_batch / score_batch_sheet / score_batch_item`：成绩发布批次的冻结快照。发布在单个 `BEGIN IMMEDIATE` 事务内一次性读取当前全部答题卡并用当时答案键核分，写入批次名单（按卷别、考生编号排序的总分）与逐题得分（按印出题号排序）；此后登记、勘误、题库改动只影响新批次，旧批次行永不更新。批次对照由相邻两批的快照逐人比对得到，新登记、总分变化、逐题前后分（含总分相抵）均可还原。
